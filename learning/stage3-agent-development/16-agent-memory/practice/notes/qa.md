# Agent Memory

## 一、它解决什么问题？

Agent 默认是无状态的——每次对话结束后，所有上下文全部丢失。下次对话时，用户必须重新自我介绍：姓名、职业、偏好……没有 Memory 的 Agent 永远"不会认识"用户。

有了 Memory，Agent 能够：
- 跨轮次记住身份和偏好（"我叫张三"→ "张三你好"）
- 跨会话持久化关键信息（昨天的对话，今天还能用）
- 基于历史做个性化响应（"你不喜欢 JavaScript，那我推荐 Rust"）

**反面案例**：没有 Memory 的客服 Agent，用户每次转接/重启对话都要把问题从头说一遍，体验极差（但实际生活中这种情况还在发生）。

## 二、核心原理

### 2.1 三层记忆架构

```
工作记忆（短期）→ 情节记忆（中期）→ 语义记忆（长期）
内存 + 全文      向量库 + 检索     知识图谱 + 混合检索
最近 10 轮        单会话级别         跨会话永久
```

### 2.2 MemoryAgent 的数据流

```
用户输入
  → [长期记忆检索] 从 FAISS 向量库搜相关历史
  → [短期记忆获取] 从内存读取最近对话
  → [分层构建 prompt] 系统指令 → 长期记忆 → 短期历史 → 当前输入
  → [LLM 生成回复]
  → [更新短期记忆] 追加 user + assistant 消息
  → [每 N 轮提取] LLM 从短期记忆中凝练事实 → 写入长期记忆
```

### 2.3 类比

短期记忆 = 工作台上的便签，随手记、随手看，但桌面空间有限，满了就得扔掉旧便签。

长期记忆 = 档案柜。重要的便签内容定期誊抄存档，要用时按关键词/语义检索调出来。不会把所有便签都存档——成本太高，也没必要。

---

## 三、短期记忆 vs 长期记忆

| 维度 | 短期记忆 | 长期记忆 |
|------|---------|---------|
| 存储介质 | 内存（list） | FAISS 向量库（磁盘可持久化） |
| 检索方式 | 顺序读取（全文） | 语义搜索（向量相似度） |
| 数据形态 | 原始对话消息 | 凝练后的事实摘要 |
| 容量 | 受限（滑动窗口 N 条） | 理论上无限 |
| 时效性 | 精确到每句话 | 只保留关键信息 |
| 写入策略 | 每轮追加 | 定期批量提取 |

## 四、我能用它做什么？

1. **个性化客服 Agent**：记住用户身份、历史订单、偏好，免去重复询问
2. **学习伴侣**：记住用户的薄弱点、学习进度、偏好风格，跨会话持续跟踪
3. **RAG + Memory 双层检索**：RAG 检索外部文档，Memory 检索用户历史——两者结合时 Agent 既"博学"又"懂你"
