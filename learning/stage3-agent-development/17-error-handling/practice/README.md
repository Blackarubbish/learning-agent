# 17 - Agent 错误处理与反射机制

## 目标

让 Agent 在工具调用失败时能自我修正（Reflection），而不是直接崩溃或胡乱重试。

## 核心概念

| 概念 | 说明 |
|------|------|
| **错误三分类** | RETRYABLE（暂时性→重试）/ PARAMETER_ERROR（参数问题→修正后重试）/ PERMANENT（永久→立即放弃） |
| **结构化错误反馈** | 按 12-Factor Agent 原则 9 压缩：只给分类+摘要+修复建议，不堆栈追踪 |
| **Reflection 反射** | LLM 根据错误反馈自主修正参数或换工具 |
| **降级策略** | 连续失败 N 次后停止循环，转交人类处理 |

## 错误累积的现实

| 单步可靠性 | 5 步成功率 | 10 步成功率 | 20 步成功率 |
|:---:|:---:|:---:|:---:|
| 95% | 77% | 59% | **36%** |
| 99% | 95% | 90% | 82% |

错误处理让每一步"失败后能修正"，打破这个指数衰减。

## 五个测试场景

| 场景 | 错误类型 | 验证点 |
|------|---------|--------|
| 天气查询超时 | RETRYABLE | Agent 根据反馈决定重试 |
| 表名拼写错误 | PARAMETER_ERROR | Agent 根据提示切换到正确表 |
| 无权限访问 | PERMANENT | Agent 1 次调用后立即停止 |
| 连续失败 | 降级触发 | 连续 2 次失败后转交人类 |
| 正常多工具调用 | 无障碍 | 成功完成天气+数据库查询 |
