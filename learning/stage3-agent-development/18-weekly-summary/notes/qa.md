# 18 - 周度总结与 Agent 项目实战

## 费曼笔记：Agent 集成

### 一、它解决什么问题？

把 FC Agent 循环、工具工程、双层记忆、错误反射四个模块集成到一个 Agent 中，解决的是**单一模块各自为战**的问题：

- 单独用 FC Agent 循环：能调用工具，但工具返回一堆原始数据，Agent 消化不了
- 单独用工具工程：工具设计得再好，没有循环机制就只能调用一次
- 单独用记忆：记住偏好但 Agent 不会用工具，什么都做不了
- 单独用错误反射：能分类错误，但没有循环就没有重试的机会

集成后形成**完整的 Agent 能力闭环**：感知（记忆检索）→ 决策（FC 循环）→ 执行（工具工程）→ 反馈（错误反射）。

### 二、核心原理

| 维度 | 作用 | 类比 |
|------|------|------|
| FC Agent 循环 | 让 Agent 多次调用工具，动态调整策略 | 人的"思考-行动"循环 |
| 工具工程 | 信息抽象 + 结构化输出，让 LLM 能可靠解析工具结果 | 好的 UI 界面，降低用户操作错误率 |
| 双层记忆 | 短期缓冲（会话内）+ 长期存储（跨会话），提升体验 | 人的工作记忆 vs 日记本 |
| 错误反射 | 三分类 + 结构化反馈，阻断错误累积的指数衰减 | 工地安全员，发现问题立刻纠正 |

### 三、反面案例 —— 没有集成会怎样？

- 没有**错误反射**的 Agent：单步 95% 可靠性，20 步后仅 36%，长任务几乎必然失败
- 没有**工具工程**的 Agent：LLM 被海量原始数据淹没，token 浪费严重，解析失败率高
- 没有**双层记忆**的 Agent：每次对话都是"初次见面"，用户需要反复声明偏好，体验极差
- 没有**FC 循环**的 Agent：退化成一个只能调用一次工具的 RAG 管道

### 四、我能用它做什么？（3 个具体场景）

1. **企业知识助手**：记住每个员工的关注领域（记忆），搜索内部知识库（工具），出错时自动修正参数而非崩溃（反射）
2. **代码审查 Agent**：搜索代码库、分析 diff、记录审查偏好，连续失败自动降级而非死循环
3. **学习教练**（本项目自身）：检索学习资料、生成笔记、追踪薄弱点、根据学习者偏好调整教学策略
