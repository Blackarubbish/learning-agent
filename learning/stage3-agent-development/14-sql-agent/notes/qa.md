# 14 - SQL & 数据库工具 费曼笔记

## 一、Schema 探索工具

**它解决什么问题？**

Agent 面对一个陌生数据库时，不知道有哪些表、每列什么类型。直接写 SQL 纯靠猜，大概率出错。独立 schema 工具让 Agent 先"看目录"再"翻书"——了解结构 → 识别相关字段 → 生成精确 SQL。这和前端的分步加载同理：一次给太多信息（SELECT * 全表），Agent 上下文会爆炸且被无关字段干扰决策。

**反面案例**

没有 schema 工具时，Agent 只能猜列名，或者写 `SELECT *` 把全表数据拉回来——百万行 × 百列 = 决策瘫痪。

**我能用它做什么？**

- 多表数据库探索：先列出所有表，再逐表查看结构
- 与第 13 章信息抽象联动：schema 工具本身就是"一级抽象"，按需深化
- 生产场景：几百张表时，Agent 能通过 schema 工具自主定位目标表

## 二、SQL 安全校验

**它解决什么问题？**

Agent 可能产生幻觉，生成破坏性 SQL（DELETE / DROP / INSERT / UPDATE）。这种错误不是"查不到重试"的问题，而是数据被篡改或删除的不可逆灾难。安全校验是 Agent + 数据库的最后一道防线。

**反面案例**

用 `if "DELETE" in sql` 精确匹配——`delete`（小写）、`DELETE FROM` 都能绕过。正则 `\b{keyword}\b` 按独立单词匹配，能处理大小写、边界、复合词。

**我能用它做什么？**

- 只读数据库查询：安全围栏 + 自动 LIMIT，防止上下文和数据双爆炸
- 数据库 Agent 的安全基础：后续可以扩展为只允许 SELECT + 白名单表
- 审计日志：记录每次拦截，用于改进 prompt

## 核心领悟

> sqlite3 是 Python 内置的，不需要装任何东西就能跑 SQL Agent。PRAGMA table_info 和 sqlite_master 是探索 schema 的两个核心入口。工具设计时把"探索"和"查询"分开，符合单一职责原则，也让 Agent 的推理链路更清晰。
