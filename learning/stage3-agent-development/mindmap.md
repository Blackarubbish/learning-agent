# Stage 3: Agent 开发与 Tool Calling

## 12 Agent 核心概念 ReAct
### Agent vs RAG
- RAG: 单向管道, 检索→生成
- Agent: 循环, 思考→行动→观察→再思考
### Agent 三要素
- LLM: 推理引擎
- Tools: 外部能力
- 思考循环: 管理推理/行动/观察的迭代
### ReAct 框架
- Thought: 分析状态, 决定下一步
- Action: 调用具体工具
- Observation: 工具返回结果
- 重复直到得到最终答案
### 何时不用 Agent
- 任务路径固定, 步骤明确 → 普通代码
- 简单if-else能搞定 → 不要Agent
- 延迟和成本要求严格 → Workflow
- 核心原则: 简单优先, 从最简方案开始
### Reflection 雏形
- 格式错误时根据 parse_error 自我修正
### max_steps 限制
- 防止无限循环, Token成本控制

## 13 自定义工具开发
### 四个核心原则
- 信息抽象: 总结+截断+引导, 渐进式曝光
- 状态反馈: 进度+成功/失败统计+建议
- 错误恢复接口: 原因+可用选项+正确示例
- 结构化输出: 标题/编号/分段, 快速定位
### 三个练习工具
- smart_search: 截断10→3条+摘要+引导
- batch_process: 3/5成功+失败详情+处理建议
- api_fetch: 每种错误码→发生了什么→为什么→你能做什么
### 核心认知
- 70%工作在工具端, LLM只完成30%
- 同样的LLM+不同工具=不同Agent
- 工具质量决定Agent上限

## 14 SQL Agent
### 核心链路
- 自然语言→Schema探索→SQL生成→安全校验→执行→结果抽象
### Schema 探索
- 先查目录再翻书
- db_schema: 返回表结构+示例数据
- 避免 SELECT * 上下文爆炸
### SQL 安全校验
- 只允许SELECT, 拦截INSERT/UPDATE/DELETE/DROP
- 独立单词匹配, 防LLM幻觉导致数据灾难
- 权限校验在工具层, 不在prompt层
### 结果限流+信息抽象
- 自动LIMIT+超限引导
- 防止百万行数据冲垮LLM上下文
### 错误恢复
- SQL失败→提示用db_schema确认列名→LLM自主修正

## 15 Function Calling 实战
### FC vs ReAct
- 解析可靠性: 99% vs 80%
- 并行调用: 原生支持 vs 不支持
- 推理链可见性: 低 vs 高
- 适用: 生产环境 vs 调试教学
### 核心机制
- bind_tools: 工具定义绑定到LLM
- JSON Schema: 结构化定义工具参数
- ToolMessage: 工具返回结果的专用消息类型
- tool_calls token: LLM原生输出, 无需正则解析
### tool_choice 四种模式
- auto: 模型自主决定, 默认
- required: 强制调用工具
- none: 禁止调用, 纯文本回复
- 指定工具: 强制使用特定工具
### 代码复杂度
- ReAct: ~100行 循环+解析器
- FC: ~30行 循环

## 16 Agent Memory
### 为什么需要 Memory
- 无记忆: 每次对话从零开始
- 有记忆: 记住偏好/历史/任务进度
### 三层记忆架构
- 工作记忆: 当前会话历史, 内存
- 情节记忆: 本会话关键信息, 向量库
- 语义记忆: 长期偏好, 知识图谱+向量库
### 双层实现
- ShortTermMemory: 滑动窗口缓冲, 最近N轮
- LongTermMemory: FAISS向量存储, 跨会话持久化
### 设计核心问题
- 什么时候存: 重要性评分, 非全部存
- 存什么: 关键决策+用户偏好, 非原始对话
- 怎么检索: 语义检索, 非全文匹配
- 怎么用: 注入上下文, 增强响应
- 什么时候清理: 定期批量提取, 非每轮提取
### 对比
- 短期: 内存全文, 精确, 窗口有限
- 长期: 向量语义, 模糊, 持久化

## 17 Agent 错误处理
### 错误三分类
- RETRYABLE: 暂时性, 超时→原参数重试
- PARAMETER_ERROR: 参数问题→修正参数重试
- PERMANENT: 永久错误, 无权限→立即放弃
### 为什么分三类而非二类
- PARAMETER_ERROR让LLM从盲目重试变成检查参数再试
### Reflection 反射循环
- 失败→结构化错误反馈→LLM自主修正→重试
- 阻断错误累积的指数衰减
### Structured Error Feedback
- 分类+摘要+修复建议
- 不堆栈追踪, 压缩到上下文窗口
- 12-Factor Agent 原则9
### 错误累积数学
- 单步95%→5步77%→10步59%→20步36%
- 单步99%→5步95%→10步90%→20步82%
- 反射打破这个指数衰减
### 降级策略
- 连续失败N次→停止循环→转交人类
- 降级阈值≠重试次数
- 降级防止死循环, 重试控制Token成本

## 18 研究助手 Agent 集成
### 整合四大模块
- FC循环: 决策框架, bind_tools+ToolMessage
- 工具工程: 可靠性, search/summarize/save_note
- 双层记忆: 体验, 短期缓冲+长期FAISS
- 错误反射: 安全网, 三分类+降级
### 架构流程
- 用户输入→长期记忆检索→短期记忆注入→FC循环
- →工具执行 信息抽象+状态反馈
- →失败→工具分类→反馈→重试/降级
- →更新短期记忆→最终答案
### 模块职责边界
- FC循环=决策框架: 只管推理-调用循环
- 工具工程=可靠性: 保证单次调用成功率
- 记忆=体验: 消除重复声明摩擦
- 反射=安全网: 阻断错误累积衰减
### 错误分类权威来源
- 工具的category是唯一权威
- classify_error只做意外异常兜底
