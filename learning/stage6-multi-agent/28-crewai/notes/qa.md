# CrewAI 角色驱动的任务协作

## 一、它解决什么问题？

让多个 Agent「专人做专事」。

每个 Agent 有明确的 role / goal / backstory，每个 Task 有明确的 description / expected_output / agent / context。这样每个 Agent 只需要关心自己负责的任务，上下文更干净，流程更清晰。

## 二、核心原理（用类比解释）

CrewAI 像一个项目经理主导的工程项目：

- **Agent** = 不同岗位的工程师（研究员、分析师、写手）
- **Task** = 项目中的具体工单，有交付物和负责人
- **Crew** = 整个项目，按 `process` 决定是顺序施工还是由经理统一调度
- **context** = 前置工单的交付物，只把必要信息传给下游

相比 AutoGen 的「会议室讨论」，CrewAI 是「按图纸施工」。

## 三、反面案例 —— 如果没有它，会发生什么？

如果直接用一个大 Agent 或 AutoGen GroupChat 做流水线任务：

1. **上下文混乱**：所有历史消息都堆在共享 history 里，每个 Agent 都被不相关的信息干扰
2. **任务边界模糊**：AutoGen 以角色驱动，没有显式的任务对象，容易出现该分析的时候去检索、该写总结的时候去分析
3. **执行不可控**：无法保证某一步一定被执行、一定按顺序执行、一定基于前置输出执行
4. **难以审计**：看不到每个步骤的独立交付物，出问题难以定位

## 四、我能用它做什么？（3 个具体场景）

1. **企业文档入库流水线**：解析 → 分类 → 合规审查 → 分块向量化 → 入库，每一步都是明确任务
2. **标准化报告生成**：研究 → 分析 → 写作 → 审核，按固定顺序交付
3. **自动化代码审查流水线**：静态检查 → 安全审查 → 性能审查 → 可维护性审查
