# Agent 核心概念 (ReAct)

## 一、它解决什么问题？

LLM 单独使用时只能"想想然后回答"，无法与外部世界交互。当用户问的问题需要**计算、查数据、调用 API** 时，纯 LLM 要么编造答案（幻觉），要么直接说"我不会"。

Agent = LLM + Tools + 思考循环，让 LLM 能**调用外部工具**来完成任务。

## 二、核心原理（用类比解释）

ReAct 循环就像**一个实习生使用计算器**：

1. **Thought**（思考）：实习生看到问题 "15 * 7 + 3"，心想"这需要算一下"
2. **Action**（行动）：拿起计算器，输入 `15 * 7 + 3`
3. **Observation**（观察）：计算器显示 `108`
4. **再思考**：实习生确认 "108 就是答案"
5. **Final Answer**：写下答案交给老板

和传统 RAG 的区别：RAG 是单向管道（问题 → 检索 → 生成），Agent 是循环（思考 → 行动 → 观察 → 再思考...直到得出答案）。

## 三、反面案例 —— 如果没有 Agent，会发生什么？

- 纯 LLM 做计算 `15 * 7 + 3`：可能算对，也可能算错（概率问题），且每次用的 token 都用来"背"答案而非精确计算
- 纯 LLM 查数据库：完全做不到，只会编造数据
- 硬编码 if-else 流程：固定流程可以，但遇到新场景（用户说"帮我把结果翻倍"）就无法适应

## 四、我能用它做什么？

1. **多步推理 + 工具调用**：用户说"统计这篇文档有多少个 ReAct 相关的段落，然后计算占总段落数的比例" → Agent 先用字符串工具统计，再用计算器算比例
2. **数据库查询 Agent**：用户用自然语言问"上周销量最高的 5 个产品是什么" → Agent 转成 SQL → 执行 → 解读结果
3. **调试助手**：Agent 可以读代码 → 发现问题 → 运行测试 → 根据结果修正 → 最终定位 bug

## 五、和已有知识的关联

- **RAG**：RAG 是 Agent 的一种特殊工具——Agent 调用的工具可以是检索器
- **LLM**：Agent 把 LLM 从"答案生成器"升级为"决策中心"
- **Function Calling**（第 15 章）：ReAct 的手写版，OpenAI/Anthropic 把 Thought/Action 解析内建到了模型里
- **Agent Memory**（第 16 章）：ReAct 循环的上下文就是最原始的 Memory

## 六、我还困惑的地方

**Q: ReAct 的 "思考" 真的只是让 LLM 输出一个 Thought 标签吗？这算什么思考？**

A: Thought 不是装饰性标签，而是 LLM 的**计算空间**。

关键原理：LLM 是自回归的——每生成一个 token，之前的所有 token 都是后续生成的上下文。当模型先生成 Thought 再生成 Action 时，Thought 产生的 token 会**条件化**后续 Action 的概率分布。

类比：给 LLM 一张草稿纸。如果没有 Thought，模型相当于心算——可能出错。有了 Thought，模型把中间推理写下来，后面的 Action 就能"看到"这些推理，决策质量更高。这和 Chain-of-Thought（"Let's think step by step"）原理相同。

更深层次：
- ReAct 的 Thought 是**显式思考**（用户可见），本质是 prompt 工程 + 自回归特性
- Claude thinking mode / o1/o3 是**隐式思考**（内部推理，不输出或输出后丢弃）
- Tree of Thoughts 是**多路径思考**（同时探索多条路径，选最优）
- Reflexion（第 17 章）是**反思**（看到自己的输出后评价并修正）

认知校准：说 Agent "会思考"是拟人化。精确表述是：显式推理 token 通过自回归机制提升了后续 token 的决策质量。第 15 章 Function Calling 会看到，OpenAI/Anthropic 把这层思考内建到了模型里——不再需要手动解析 Thought/Action。

**Q: 学了这章后我发现 LLM 的"思考"只是提示工程 + 自回归，是否意味着 Agent 的"智能"被高估了？**

恰恰相反。理解了这个机制，你反而能更准确地发挥 Agent 的能力：

- **不低估**：自回归 + 显式推理 token 是真实有效的认知增强，不是魔术但也不是骗局
- **不高估**：Agent 每一步可靠性不是 100%（95% × 20 步 = 36%），所以 max_steps 要小，任务要聚焦
- **用到刀刃上**：Anthropic 的原则——不确定的任务用 Agent，确定的流程用普通代码。当你理解了 Thought 的本质，就能在设计 Agent 时做出更好的 trade-off：多给一步思考的 token 预算，比多给一个工具更有价值
