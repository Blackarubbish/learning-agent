# 11 - 周度总结：Advanced RAG 系统集成 — 费曼笔记

## 一、它解决什么问题？

把 Week 2 学的 5 个独立技术串成一条完整的生产级 RAG 管线，并对比"优化前 vs 优化后"的效果差异。单学每个技术时只知道"有这个工具"，但不知道它们如何协同工作。

## 二、核心原理

```
原始查询 → Multi-Query 改写 → BM25 + 向量 → RRF 融合 → Rerank 精排 → LLM 生成
   ↑                           ↑                              ↑
 提高召回覆盖面            互补检索维度                   精细选择 top-k
```

类比：搜索引擎先做查询补全（Multi-Query），然后同时跑关键词索引和语义索引（BM25+向量），用加权公式合并两路结果（RRF），最后用精排模型挑出最相关的 3 条（Rerank），交给 LLM 生成答案。

## 三、反面案例 —— 如果没有这些优化

今天亲眼看到的现象：

1. **Prompt 少一句话导致幻觉**：Naive RAG 少写了"如果上下文中没有相关信息，请如实说明"，结果模型在回答"OpenAI 有哪些模型？"时编造了 DALL-E、Whisper、Codex 等完全不存在的文档内容。

2. **单路检索的盲区**：纯向量检索在"用什么语言做向量检索？"这个查询中，召回了"Transformer"和"NLP"（语义相关但无实际信息），而混合检索额外召回了"Python"——因为 BM25 和向量互补，RRF 融合后覆盖了各自盲区。

## 五、关键认知

- **Faithfulness 是幻觉检测的第一道防线**：逐句检查答案是否被上下文支持，比 Answer Relevancy 和 Answer Correctness 更直接
- **Rerank 是粗排→精排的第二步**：精排算力消耗大，所以先用低成本混合检索粗筛，再用 Rerank 精细筛选
- **Multi-Query 决定天花板**：垃圾进垃圾出，查询改写是所有下游检索的前提
