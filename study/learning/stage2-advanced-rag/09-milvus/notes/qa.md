# Milvus 向量数据库

## 一、它解决什么问题？
> FAISS 只是向量索引，不是数据库——不支持增删改、属性过滤、持久化、分布式。Milvus 是真正的向量数据库，能处理复杂过滤条件、数据持久化到磁盘、支持分布式扩展，是可以直接上生产的选择。

## 二、核心原理（用类比解释）
> FAISS 像一个内存里的数组——建好就固定了，想改得重建。Milvus 像一个真正的数据库——你可以随时 insert / upsert / delete / query，数据自动落盘，重启不丢失。还支持 SQL-like 的 filter 表达式做属性过滤，比如 `year >= 2024 and category == "AI基础"`。

## 三、反面案例
> 如果只用 FAISS 上生产：
> 1. 数据只存内存，重启后全丢，需要重建索引
> 2. 数据量大时内存占用不可控
> 3. 不支持分布式，单机扛不住大数据场景
> 4. 不支持属性过滤，想按条件筛选只能在代码层做，效率低

## 四、我能用它做什么？
> 1. 需要频繁增删改的 RAG 系统（文档库动态更新）
> 2. 需要按属性过滤的检索场景（按时间、分类、标签筛选）
> 3. 数据量大到单机内存扛不住，需要分布式存储

## 五、和已有知识的关联
> - FAISS（04章）：Milvus 是 FAISS 的生产级替代，核心检索能力相同，但多了数据库能力
> - CRUD 全流程：insert → query → search → upsert → delete
> - 部署方式：Milvus Lite（本地开发） / Standalone（单机） / Cluster（分布式）
