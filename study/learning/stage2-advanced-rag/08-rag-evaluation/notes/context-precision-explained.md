# Context Precision (上下文精确度) 详解

## 一句话概括

Context Precision 衡量检索结果中，相关文档是否排在了前面——本质是评估**排序质量**。

## 核心问题

> 排在前面的文档里，有多少是真正相关的？

检索 10 篇文档，如果 3 篇相关的都排在前 3 位，Precision 很高；如果 3 篇相关的散落在第 2、7、10 位，Precision 很低。

---

## 为什么排序比"有没有"更重要？

RAG 系统通常只把 top-k 文档喂给 LLM（受上下文窗口限制）。如果相关文档排在第 8 位但 top-k=5，等同于没检索到。

```
场景 A: 相关文档排前面（好）
  [相关✓, 相关✓, 不相关✗, 不相关✗, 不相关✗]  → top-2 就够了

场景 B: 相关文档排后面（差）
  [不相关✗, 不相关✗, 不相关✗, 相关✓, 相关✓]  → top-5 才拿到，前面 3 篇是噪声
```

---

## 计算过程

Context Precision 使用 **Average Precision** 的思想：对所有相关文档位置的 precision 取平均。

### Step 1：标记每个位置是否相关

```
检索结果: [Doc1, Doc2, Doc3, Doc4, Doc5]
相关性:    [ ✓,    ✗,    ✓,    ✗,    ✓  ]
位置:        1     2     3     4     5
```

### Step 2：计算每个相关位置的 precision@k

```
Doc1 (k=1): precision@1 = 1/1 = 1.0    (前 1 个中 1 个相关)
Doc3 (k=3): precision@3 = 2/3 = 0.67   (前 3 个中 2 个相关)
Doc5 (k=5): precision@5 = 3/5 = 0.6    (前 5 个中 3 个相关)
```

### Step 3：取平均值

```
Context Precision = (1.0 + 0.67 + 0.6) / 3 = 0.76
```

**只对相关文档位置取平均**，不是所有位置。

---

## 完整示例

### 案例 1：完美排序

```
检索结果: [相关✓, 相关✓, 相关✓, 不相关✗, 不相关✗]

precision@1 = 1/1 = 1.0
precision@2 = 2/2 = 1.0
precision@3 = 3/3 = 1.0

Context Precision = (1.0 + 1.0 + 1.0) / 3 = 1.0
```

### 案例 2：最差排序

```
检索结果: [不相关✗, 不相关✗, 相关✓, 相关✓, 相关✓]

precision@3 = 1/3 = 0.33
precision@4 = 2/4 = 0.5
precision@5 = 3/5 = 0.6

Context Precision = (0.33 + 0.5 + 0.6) / 3 = 0.48
```

**同样 3 篇相关文档，排序不同，分数差距巨大。**

### 案例 3：全部不相关

```
检索结果: [不相关✗, 不相关✗, 不相关✗]

Context Precision = 0 / 0 = 0.0  (没有相关文档，定义上为 0)
```

## Context Precision vs Context Recall

| 维度 | Context Precision | Context Recall |
|------|-------------------|----------------|
| 核心问题 | 相关文档排得靠不靠前？ | 需要的信息检索到了多少？ |
| 关注点 | 排序质量 | 覆盖度 |
| 高分条件 | 相关文档都在 top 位置 | 所有需要的信息都被检索到 |
| 低分意味着 | 排序差，好文档被埋在后面 | 检索漏了关键信息 |
| 优化方向 | Rerank、调优 Embedding 模型 | 增大 top-k、混合检索 |

### 经典权衡

```
策略 A: top-k=3
  → Precision 高（只返回最相关的），Recall 可能低（遗漏了排第 4-10 的相关文档）

策略 B: top-k=20
  → Recall 高（尽量覆盖），Precision 可能低（混入很多不相关文档）

最优解: 先 top-k=20 大范围召回，再用 Rerank 精排 → Precision 和 Recall 都高
```

---

## Context Precision 低的原因与对策

| 原因 | 说明 | 对策 |
|------|------|------|
| Embedding 模型不够好 | 语义相似但不同主题的文档排在前面 | 换更好的 Embedding 模型 |
| 没有使用 Rerank | 初步检索排序粗略 | 加入 Rerank 精排 |
| 查询歧义 | "Apple" 检索到了水果相关文档 | 查询变换（Multi-Query、HyDE） |
| 文档质量差 | 文档本身内容混乱，Embedding 质量低 | 改进文档切分和处理 |
