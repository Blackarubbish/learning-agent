# RRF (Reciprocal Rank Fusion) 融合算法

## 要解决的问题

多路检索（比如 BM25 + 向量检索）各返回一个排序结果，怎么合并成一个最终排名？

直接按分数合并不行——BM25 分数和向量相似度分数**量纲不同**，不能直接比较。BM25 分数可能是 0-10，向量 L2 距离可能是 0.5-2.0，谁大谁小没有意义。

## 核心思路

RRF 的关键洞察：**不比分数，比排名。**

把每路检索的排名位置转化为分数，然后累加。排名越靠前，分数越高。

## 公式

```
RRF_score(doc) = Σ  1 / (k + rank + 1)
```

- `rank`：文档在该路检索中的排名（从 0 开始）
- `k`：平滑参数，经典值 60

## 具体例子

假设 BM25 和向量检索各返回 3 个结果：

| 排名 | BM25 结果 | 向量检索结果 |
|---|---|---|
| 0 (第1名) | 文档A | 文档C |
| 1 (第2名) | 文档B | 文档A |
| 2 (第3名) | 文档C | 文档D |

k=60 时，计算每篇文档的 RRF 分数：

| 文档 | BM25 贡献 | 向量贡献 | RRF 总分 |
|---|---|---|---|
| A | 1/(60+0+1) = 0.0164 | 1/(60+1+1) = 0.0161 | 0.0325 |
| B | 1/(60+1+1) = 0.0161 | — | 0.0161 |
| C | 1/(60+2+1) = 0.0159 | 1/(60+0+1) = 0.0164 | 0.0323 |
| D | — | 1/(60+2+1) = 0.0159 | 0.0159 |

最终排名：**A > C > B > D**

文档A 两路都排名靠前，所以总分最高。文档C 也是两路都有，紧随其后。

## 参数 k 的作用

k 控制排名差异的影响程度：

| k 值 | 效果 | 适用场景 |
|---|---|---|
| 小 (如 1) | 排名差异影响大，第1名和第2名分数差距大 | 信任排名，想要"赢者通吃" |
| 60 (经典值) | 排名差异影响适中 | 通用场景 |
| 大 (如 100) | 排名差异影响小，更平滑 | 不想某个检索路主导结果 |

**为什么通常选 60？** 这是原论文实验推荐值，在大多数场景下表现稳定。

## RRF 的优势

1. **无量纲问题**：只用排名不用原始分数，不同检索系统的结果可以直接融合
2. **对异常值鲁棒**：不会因为某个检索系统的分数分布异常而影响整体结果
3. **实现简单**：只需要排名，不需要访问检索系统的内部分数
4. **两路都认可的文档自然排名更高**：文档在多路都出现且靠前，分数叠加后自然上升

## 代码实现对应

```python
def rrf_fusion(results_list, k=60):
    doc_scores = {}
    for results in results_list:  # 遍历每路检索结果
        for rank, doc in enumerate(results):  # 遍历该路的排名
            doc_id = doc.page_content[:100]  # 文档唯一标识
            score = 1 / (k + rank + 1)  # 排名转分数
            doc_scores[doc_id] = doc_scores.get(doc_id, 0) + score  # 累加
    # 按总分排序
    return sorted(doc_scores.items(), key=lambda x: x[1], reverse=True)
```

## RRF vs 其他融合方式

| 融合方式 | 做法 | 问题 |
|---|---|---|
| 分数归一化后相加 | 把各路分数归一化到 [0,1] 再相加 | 归一化方式影响大，分布不同时会偏斜 |
| 取交集 | 只保留两路都返回的文档 | 可能结果太少，丢失单路有价值的文档 |
| 取并集按分数排 | 合并后按原始分数排 | 量纲不同，无法比较 |
| **RRF** | **按排名转分数累加** | **简单、鲁棒、无需归一化** |
